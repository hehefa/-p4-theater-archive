# 私有主目录与公开范围投影

完整盘点与公开目录分开维护。私有主目录保留 1,740 个物理视频文件的永久编号、原始版本关系及先前文本；当前公开投影只保留 1,445 个候选视频文件。295 项由家庭混合候选排除或单独官网关联待核实规则挡住，不能把它们统称为已确认家庭录像。

原片不搬移，私有编号不销号。当前 Git 树删去的字幕在私有端保留原字节与哈希；这项操作没有重写已有 Git 历史，不能描述为历史抹除。

## 两项必要检查

1. **项目关联**：官网或主档案必须提供可复查的实质项目或实践背景，不能只靠文件夹名或 folder-only 标签。当前 8 项的官方内容说明和完整原片 SHA 是最强匹配；其中 5 段是实践讨论，不冒充正式剧目。这不要求每个未来新文件预先上过官网，也不要求 A、B 两站同时存在：未公开原片可用明确官方项目／事件记录与实际视频内容交叉审阅建立逐文件证明，SHA 用来绑定实际被审阅的字节版本。
2. **家庭排除**：家庭材料不能公开。混合目录默认排除，工作坊例外必须有该条素材的官方证据并经明确复核；新路径、改大小写或重复字节不能自动绕过禁发清单。

官网关联不代表已经全片听校、全程观看或完成隐私审核。平台显示 public 也不能自动证明项目内容相关。

## 持久防反弹

公开树的 `.p4-public-scope.json` 声明必须使用投影流程。它保存排除身份的摘要、明确允许的字幕版本及计数，不保存私有源路径。

- 直接向公开树执行 `archive_catalog.py import` 会被拒绝。
- 旧的字幕批量合并命令不能直接向这棵公开树恢复正文。
- 新字幕须既在明确版本白名单内，又绑定官方证明的相同完整原片哈希；其他正文保持 `withheld_pending_official_item_evidence`。
- 排除清单按永久 ID 和归一化 Windows 路径前缀检查；已知相同完整 SHA 的复制品也不能借换路径进入公开投影。
- 不满足规则的新素材可以留在私有主目录等待复核，不能据候选目录状态新增公开上传。

当前新上传开关全部关闭，是本轮已知版本与待查重状态的决定，并非永久禁止新文件入档。未来可在私有政策的 `new_upload_authorizations` 中按具体 asset/file/SHA 登记完成的官方背景、实际内容、家庭隐私及查重检查；还须通过当前来源指纹检查。家庭排除始终优先，任何新上传授权不能覆盖禁发项。没有这些记录时继续 fail-closed。

## 更新流程

先在公开仓库外的私有主目录完成盘点与修改。后台核验运行时不要同时刷新它正在写入的缓存。维护者确认范围证据后再投影：

```sh
python -X utf8 scripts/project_public_scope.py --public-root <公开仓库> --master-root <仓库外私有主目录> --local-state <私有状态目录> --exclusions <私有禁发清单> --official-evidence <具体来源官方证据> --allow-caption <明确允许的字幕编号>
python -X utf8 scripts/archive_catalog.py validate --root <公开仓库>
python -X utf8 -m unittest discover -s tests -v
```

可重复传入官方证据与字幕编号。投影先在私有暂存目录生成并检查，再替换当前公开范围；同时过滤素材、物理文件、字幕、平台关系、字节相同组和事件引用。没有证据的字幕不会因重跑而自动恢复。

汇总中的 `private_master_inventory_video_files`、`public_selected_video_files` 和 `public_excluded_video_files` 分别表示完整私有盘点、当前公开候选和当前排除量。公开候选数量不是上传授权数量。
