# 既有回执与当前目录的接入

`scripts/publication_receipts.py` 是离线回执适配器，不是上传器。它只读取明确给出的 JSON 回执和当前 `catalog/`；不会扫描磁盘、读取或计算影音哈希、转写、联网或修改现有实体表。Python 3 标准库即可运行。

## 与当前公开范围一体检查

工具自动读取 `--catalog-dir` 同级仓库根的 `.p4-public-scope.json`；投影目录若丢失该文件会拒绝运行，不增加绕过参数。来源表的 `public_scope.policy_sha256` 对规范化 JSON 计算摘要，因此原文件 LF/CRLF 不改变策略身份。策略改变后旧投影检查失败，须按新范围重新预览。

逐项候选只可基于以下既有证据保留：

1. **官方逐项来源证据**：相同完整 SHA/bytes 的当前文件、对应素材、明确项目来源决策和官方 A/B 站证据相互吻合；不能只凭文件夹名或项目名。
2. **当前已有平台关联**：video ID 已在当前公开 `publications.json`，且所指素材/文件没有被范围排除。这里只生成 `existing_publication_metadata_only` 的来源相关关系，并列出现有 publication ID。若原版本 SHA/bytes 无法对应当前已保留版本，则连这些版本细节也扣除，不能借一个重复 video ID 带回未知源身份。

排除身份摘要优先于以上两种证据。公开目录中的 pending 候选状态或平台 public 状态不构成新内容公开依据。当前 16 条平台记录保留原有 metadata-only 核验边界；适配器不修改它们、不补造缺失的观察时间、不继承其 verified、不推定上传流哈希、播放或字幕已通过。

## 状态与来源

- `historical_claim`：回执记录的状态和记录时间。VORTEX 的 `public` 仅作为历史台账声明；不会自动升级为平台回读。
- `historical_platform_observation`：仅在既有回执明确带平台观察字段时标为 `receipt_reports_platform_observation`。原始页面/响应不进入公开投影；这不是适配器重新核验的结果。处理、隐私、播放分别保存，不相互替代。
- `current_platform_observation`：本离线工具固定为 `not_performed`，不能改写成今天已核验。
- `evidence.receipt_sha256`：输入 JSON 回执字节的 SHA，不是重新计算媒体的 SHA。`record_key` 使用回执中 `assets` 的零起始序号；若原来是对象，则按原 JSON 顺序取值。结合原回执摘要可在私有侧准确复查，公开侧不复制原键中的本机路径。
- `receipt_file_version`：只有符合当前逐项范围时才投影回执明确给出的文件 SHA/bytes；纯平台来源相关记录可为 `version_details_withheld_by_current_public_scope`。它不证明所有同项目原片、代理或重剪版相同。允许保留的 `historical_claim.reported_upload_time` 原样保存上传时间声明；缺时区不推定为 UTC。`recorded_at` 使用有时区的回执记录时间。

来源表保存回执摘要、适配器、频道 ID、原行数、历史状态计数、公开行数、非公开省略量、范围扣除量及项目外部编号，便于另一维护端找到同一份回执。实际回执路径、上传 session、私有 video ID、文件路径、令牌、原始平台回复均不进入公开表。源回执仍需由拥有它的维护端保管，公开摘要不能还原或认证其全部内容。

## 本地预览与检查

先检查已经提交的公开候选；不需要私有回执，也不需要联网：

```sh
python3 scripts/publication_receipts.py check --candidates catalog/publication-candidates.json --sources registry/publication-sources.json
python3 -m unittest discover -s tests -p test_receipts.py -v
```

预览一份自己持有的真实回执，默认把两个公开表写到标准输出。`--receipt` 必须显式指定，不会按目录自行发现文件：

```sh
python3 scripts/publication_receipts.py preview --adapter vortex --source-id vortex-source-archive-20261022 --receipt "<本机 publication-ledger.json 的路径>" --project-id project:c559eef1-ec1c-41c6-b829-9c1471d27278 --external-project-ref a.p4theater.cn:project-code=P4C-014
```

需要落盘时，同时给出 `--output <候选表路径>` 和 `--sources-output <来源表路径>`。二者都先在内存校验，再写为 UTF-8/LF JSON；指定路径的原输出会被替换。建议先写独立工作输出供比较；两份文件并非跨文件事务，提交前运行 `check` 确认它们对应。

`--append` 会读取这两份现有公开表，仅替换同一 `source-id` 的行并保留其他来源；相同回执、参数和目录重跑会得到相同字节。不带 `--append` 是单来源输出，不能用它覆盖一份包含其他来源的正式聚合表。

其他适配器为 `human-surrender`（`upload_receipt.json`）与 `fa`（`upload_receipts.json`）。不要把 `session.json`、认证文件或平台原始响应当成回执。当前表的 3 个 `source-id`、适配器及摘要都可在 `registry/publication-sources.json` 中复查。私有路径不写进命令说明、Git 或公开交接。

## 明确版本对应后导出绑定

本工具只支持**同一文件版本**的绑定导出：

1. 当前 `asset_id` 与 `file_id` 必须存在且双向关联。
2. 显式映射中的完整 SHA 和非零 bytes 必须同时等于回执版本、当前文件记录及当前 checksum 证据。
3. 对已有项目关联，还要核对目标素材属于该项目。只凭名称、近似项目、相机文件名或大小均不允许绑定。
4. 映射 `identity_confirmed: true` 表示维护者已经确认这条身份对应；它不是新的发布批准、试听或版权门槛，也不会被写成平台 verified。

映射文件保存在本地工作输出即可，不包含路径：

```json
{
  "schema_version": 1,
  "kind": "publication_mappings",
  "items": [
    {
      "candidate_id": "<现有 publication-candidate ID>",
      "asset_id": "<当前 asset ID>",
      "file_id": "<当前 file ID>",
      "sha256": "<回执与文件记录相同的64位小写SHA>",
      "bytes": 123,
      "identity_confirmed": true
    }
  ]
}
```

```sh
python3 scripts/publication_receipts.py export --candidates catalog/publication-candidates.json --sources registry/publication-sources.json --mappings "<本机明确映射 JSON>" --output "<独立绑定输出 JSON>"
```

失败不替换输出；成功仅生成 `publication_bindings`，**不修改** `catalog/publications.json`、素材或文件记录，也不向平台上传。空映射可得到空输出，但不会把扣除或未匹配项变成确认项。绑定还要求文件属于该候选当前 scope 的 `eligible_file_ids`；本批没有真实绑定输出。

转封装、代理、修复、剪辑版可能有不同 SHA、字节与时钟。须另存明确的原片→发布副本/剪辑区间关系，再按实际版本设计关联；不能为了通过本工具而把它们的 SHA 改成一样。Workbench 既有片段已经是 `source_zero`，接入时不能再加一次窗口偏移。

## 范围与规则

实体身份仍用现有 UUID；accession 是展示别名；A 站代码/slug 通过 namespace 对照。P4 自有素材沿用用户既有版权声明与发布授权，本工具不另设人工审批 gate；用户最新明确的官方逐项关联与家庭排除范围持续生效。未知作品归属、版本对应和未完成的平台状态仍按证据保留。

`schemas/publication-receipt.schema.json` 描述候选、来源、映射与绑定四种表，所有公开层级均列明允许字段。运行时 `check` 另外校验跨记录 ID、SHA/bytes、来源计数、固定公开 URL、历史与当前观察边界。直接编辑候选不构成新的真实性证明；应回到明确回执重新预览并审阅差异。

本批未重新扫描/计算媒体哈希、未 ASR、未上传、未重新回读平台；没有调整现有实体目录、编号、字幕正文或项目归属。
