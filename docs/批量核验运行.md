# 本地批量核验运行

`scripts/verify_library.py` 顺序读取本地文件，逐个计算完整 SHA-256，再运行 ffprobe 读取容器与音视频流元数据。它不上传、不调用 GPU，也不执行全片解码。一次只处理一个文件，避免多条核验任务争抢同一存储设备。

## 小样与全量

以下命令从本仓库根目录运行。私有 `local_state` 必须位于公开仓库之外，且已有导入生成的 `mapping.json`。

```sh
python -X utf8 scripts/verify_library.py --root . --local-state ../local_state --job-dir ../local_state/verification_sample --only-file P4-F000001 --only-file P4-F001071 --only-file P4-F000203 --only-file P4-F001623
python -X utf8 scripts/verify_library.py --root . --local-state ../local_state --job-dir ../local_state/library_verification_full
```

第一条是本批目录中空文件、已有可信哈希的 MOV、修复 MP4 与 MTS 的代表性样本；以后更新目录时应重新选择实际存在的编号。小样与全量使用不同任务目录。

`--limit 10` 表示本次最多新增处理十个文件。再次运行相同任务目录会复用已完成且快照指纹仍一致的结果；已经完成的文件不会重复读取整个视频。单个文件中途停止时，下次从该文件重新开始。

## Windows 隐藏窗口启动

维护者确认小样和任务范围后，可在仓库根目录的 PowerShell 启动。下面的路径变量在本地解析，不应写入公开目录。

```powershell
$archiveRoot = (Resolve-Path '.').Path
$archiveState = (Resolve-Path '../local_state').Path
$verifyJob = Join-Path $archiveState 'library_verification_full'
New-Item -ItemType Directory -Force -Path $verifyJob | Out-Null
$verifyScript = Join-Path $archiveRoot 'scripts/verify_library.py'
$verifyPython = (Get-Command python).Source
$verifyArguments = '-X utf8 "{0}" --root "{1}" --local-state "{2}" --job-dir "{3}"' -f $verifyScript, $archiveRoot, $archiveState, $verifyJob
$verifyProcess = Start-Process -FilePath $verifyPython -ArgumentList $verifyArguments -WorkingDirectory $archiveRoot -WindowStyle Hidden -RedirectStandardOutput (Join-Path $verifyJob 'stdout.log') -RedirectStandardError (Join-Path $verifyJob 'stderr.log') -PassThru
Get-Process -Id $verifyProcess.Id
Get-Content -LiteralPath (Join-Path $verifyJob 'progress.json') -Raw
```

启动后应核对真实进程仍存在，并看到 `progress.json` 的当前阶段、时间和计数或当前文件字节数持续前进。不要只凭启动命令返回就写“核验完成”。

## 断点、锁和结果

| 文件 | 用途 |
| --- | --- |
| `run_config.json` | 本次选定文件及大小、修改时间指纹摘要；快照不同则拒绝在同一任务内混用 |
| `progress.json` | 当前进度、处理状态计数、当前文件与哈希字节数 |
| `events.jsonl` | 追加运行日志 |
| `results/` | 每个物理文件的结果与原始 ffprobe 输出，包含私有信息，仅留本地 |
| `completion.json` | 本次停止原因、选定文件是否全部处理，以及核验范围 |
| 私有状态中的 `hash_results.json` | 可供下次导入复用的完整哈希 |
| 私有状态中的 `probe_results.json` | 可供下次导入使用的白名单元数据 |

同一私有状态目录只允许一个此类核验进程。锁由操作系统持有，进程退出或崩溃后释放；留下锁文件本身不代表任务仍在运行。不要同时另开旧哈希程序读取同一批原片。

在读取前、哈希后与 ffprobe 后，程序比较文件大小和纳秒修改时间。发生变化时记录 `source_changed`，不接受旧哈希，也不把这次结果当成原快照已通过。快照变更需要重新盘点并建立新的任务目录；旧结果保留。

`completed_with_findings` 表示所有选定文件已处理，同时存在空文件、读取失败或其他待处理问题。只有 `all_selected_sources_processed=true` 才代表本任务选定范围已走完；它不能证明人工审阅、字幕听校或全片解码已完成。

## 刷新公开目录

核验结果先保存在私有状态。核验完成后，按 [数据目录说明](数据目录.md) 导入到私有主目录，再做 [公开范围投影](公开范围投影.md)。不要直接向当前公开树导入完整盘点。随后运行：

```sh
python -X utf8 scripts/archive_catalog.py validate --root .
python -X utf8 -m unittest discover -s tests -v
```

仅提交公开目录的变化。任务日志、实际源路径、原始 ffprobe 标签和私有映射不进入 Git。
