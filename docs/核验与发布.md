# 核验与发布

本流程让每条视频、字幕和线上链接都能回到具体档案记录。各步骤分别保存结果；任何一步待核验，都不会被其他步骤的通过覆盖。

## 1. 登记与确认归属

登记物理文件、来源集合、候选项目与事件。优先沿用已有编号，记录原版、修复版、剪辑版及副本之间的关系。文件夹归属只提供线索，混合材料需要逐条确认。

保留公开范围待确认、外部参考或私人材料的区分。只公开已确定属于本档案公开范围的内容；公开目录中的最小记录也不包含私人内容详情。

## 2. 核对文件

先记录大小、容器、音视频流与可读取时长，再按批次进行 SHA-256 和全程解码。零字节、读失败、无音轨、空识别及损坏分别记录。全程解码通过仍不代替人工观看；人工观看只标注实际覆盖的范围。

需要修复时另存输出，保留原片。发布队列明确选用哪份文件以及理由，不仅凭文件名中有 `fixed` 判断可用。

## 3. 核对字幕与翻译

字幕绑定到具体文件与时间轴；检查中文原文、英文翻译和双语合并版本是否一致。机器格式检查至少核对编号、时间码、正时长、越界与重叠。

人工审核分开记录：听校原文、核实专名、翻译复核、抽样观看和全片观看。空字幕可以表示未识别到文字，不能自动解释为没有声音或没有事件。机器翻译、机器转写始终有清楚的来源与版本。

本地检验后仍须保留字幕版本哈希。公开后再修订时，保存旧版和修改说明，更新平台字幕，并重新检查线上版本。

## 4. 准备上传清单

每条待上传材料至少确认：

- 档案编号、选用文件、项目与事件归属。
- 视频标题、简介、播放列表与是否存在相同的线上视频。
- 日期的依据；无法确认时不在标题中写成确定日期。
- 目标频道的实际频道 ID、发布可见性与适当的公开范围。
- 各语言字幕的具体版本和审核状态。

标题和简介优先写清项目、事件、日期线索和档案编号；简介提供对应档案条目。已有线上视频先建立映射，避免重复上传。频道名称相似时，核对频道 ID 后再继续。

## 5. 上传与回读

等待平台上传与处理完成，保存实际返回的视频 ID。记录真实可见性，不用“开始上传”代替“已完成发布”。上传字幕后，分别确认字幕语言、版本与显示情况。

从视频的实际访问页面检查：链接能打开，画面和音轨正确，首尾与抽查时间点可播放，字幕可选择且时间点对应。平台自动生成字幕与人工上传字幕分别记录。若平台处理、账户验证或配额阻塞，保留队列位置和原因，解决后从断点续跑。

## 6. 更新档案

把视频链接关联到选用的物理文件、字幕版本、项目和事件，并区分人工声明与平台核验。当前 `record-publication` 命令只登记人工提供的信息，记录保持 `operator_reported`，平台回读状态保持 `not_recorded`；它不证明上传成功，也不会解除素材原有的审阅或公开范围待核实状态。

只有实际回读并留存可复查证据，才能说明相应范围已核验；记下观察时间、来源页面、播放和字幕检查的具体覆盖范围。当前命令没有录入平台核验回执的入口，人工声明不计入已核验上传数量。文件、字幕或可见性后续变化时，追加变更记录并重新核验受影响部分。维护命令见 [数据目录](数据目录.md)。

上传结果以平台事实为准：没有确认的视频 ID 就没有已完成上传的证据；视频可播放不代表所有字幕都已上线；发布副本存在不代表原始文件已完成备份。
