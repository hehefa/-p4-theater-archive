# 保存与恢复

档案需要同时保存原始内容、可检索的描述和可追踪的修改历史。GitHub、原片存储和 YouTube 各自保存不同层面的材料。

| 保存位置 | 主要职责 | 需要另行保存的内容 |
| --- | --- | --- |
| 原片存储与独立备份 | 保存原始视频、修复版、工程及完整处理产物 | 目录和校验记录也应随备份保存 |
| GitHub | 保存目录、编号、事件关联、可公开字幕、说明与修改历史 | 多 TB 的原片另存，私有路径映射不公开 |
| YouTube | 提供视频播放与字幕访问，保存发布状态与视频 ID | 平台转码副本不能替代本地原片与独立备份 |

## 原片至少要有可核对的独立副本

原片保存位置与备份位置应相互独立，并由档案编号、物理文件 ID 和哈希连接到目录。备份后核对文件数量、大小和哈希；尚未核对的备份保持待验证状态。日常编辑、转写和上传使用工作副本，避免影响唯一原件。

为每次备份记录保存位置、完成时间、核验范围和结果。公开目录只记录适宜公开的存储状态，具体设备路径、私人地址和访问凭据放在私有登记中。

## 校验计划不能替代已完成的校验

大体量素材可以分批计算 SHA-256。每批保存已处理文件、文件大小和计算结果，后续从断点继续。引用旧哈希前确认它对应当前字节版本，不能把名称相同的文件视为已经验证。

全量哈希尚未完成时，目录准确记录未计算、已有可信记录和本次已计算的区别。定期抽查备份读取能力；发现差异时保留异常文件，先比较其他副本再决定恢复。

## 文本与编号也需要备份

定期复制完整 Git 仓库或建立独立镜像，保留历史。Git 里的最新目录之外，还需要安全保存：

- 本地编号登记及旧系统标识对照。
- 物理文件 ID 与原片实际位置的私有映射。
- 校验断点、处理日志、修复证据和原始识别输出。
- 未公开材料的审核与范围判断记录。

这些私有状态不能通过将整个工作目录推送到公开仓库来备份。迁移设备后，应先验证登记与映射，再运行增量导入，防止给同一批材料重新编号。

## 恢复一次材料

1. 从档案编号找到物理文件 ID、所需版本与已有哈希。
2. 在私有映射里找到保存位置，复制到工作区。
3. 比较大小与完整哈希；视频需要时再进行全程解码。
4. 核对字幕版本与该视频的时间轴。
5. 若需要重传，保留旧平台 ID 与失效原因，新增发布记录，不抹去旧的引用历史。

## 外部平台规则

GitHub 普通 Git 存储有文件及仓库规模限制，不适合直接容纳本档案的多 TB 原片。具体规则以 [GitHub 大文件说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 为准。视频上传条件和平台限制以 [YouTube 上传说明](https://support.google.com/youtube/answer/71673?hl=zh-Hans) 为准。
