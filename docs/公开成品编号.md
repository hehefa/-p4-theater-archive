# 公开成品编号

这套编号只引用 `published/manifest.json` 中明确公开的发行版、文章、字幕、研究与图像。编号空间为 `public-edition-accession:v1`，与PC私有原片登记、P4-P/F/S编号和既有hf-img身份分别保留。它不重新分配原片编号，不改文件名，不移动、覆盖或上传原件。

| 公开成品kind | 展示号示例 |
|---|---|
| document | AR-T000001 |
| caption | AR-S000001 |
| research | AR-R000001 |
| image | AR-I000001 |

每条既有 `item.id` 是登记中的 `source_id`；原始ID以及明确声明的accession、entity_id、image_id、hf-img等标识进入带namespace的aliases。它们是来源对照，不据名称相近自动合并身份。来自原片的关联ID不能冒充同一个发行版身份。

## 主号、文件号与位置

主号按manifest首次出现的源ID追加，各kind独立递增。以后调换manifest顺序不会洗牌；同ID更新版本仍用原号，新ID只取下一号。新版本如果沿用新的源item.id，则另配新号，同时保留旧源ID映射。号段不复用，也不通过删掉最后一项来退回计数器。

每个成品有自己的文件子号，例如 `AR-I000001-F00001`。同一成品内，相同SHA-256和bytes识别同一字节版本，多个Git/Release位置可以共用这个F号；新字节版本追加下一F号。不同成品之间不借相同字节自动合并。旧F号、原位置与旧版本始终保留。

`registry/public-accessions.json` 保存：

- namespace、首次/当前manifest摘要、四个主号计数器。
- source_id、展示号、当前标题、原标识aliases及当前/历史标记。
- 每条成品的文件计数器；各文件子号、SHA、bytes及追加式locations。
- 版本的来源URL、官方背景URL、bundle版本SHA及文件位置引用。

完整位置元数据只保存一份。版本中的 `file_accession + location_sha256` 解析到这个已登记位置；bundle版本SHA按解析后的准确文件描述与来源URL计算。文件SHA与bundle SHA含义不同，均不可相互替代。

`storage=git` 表示仓库文件。`storage=release` 保留稳定虚拟path、Release包URL、archive_path及对应SHA/bytes等证明；download_url必须是实际HTTPS包地址，不能缺失或用虚拟path代替。索引直接链接download_url，不静默回退成虚拟本地链接。编号工具不下载Release，也不把虚拟path冒称本机文件。图像tiles各有文件关联与位置记录，不能把tiles数量当作品数量。登记位置的历史存在不代表今天已重新验证仍可下载。

## 初始化与增量

只有这一namespace首次建立时，由负责维护端执行：

```sh
python -X utf8 scripts/public_accessions.py assign --root . --initialize
python -X utf8 scripts/public_accessions.py check --root .
```

`assign` 默认在缺少registry时停止。`--initialize` 不能覆盖既有登记；如果NUMBERED_INDEX已存在、Git曾登记这个registry，或索引仍跟踪它，即使加initialize也拒绝重新起号，须先恢复原登记。不要为解决缺状态而删索引、换目录重新编号。

以后更新先完成公开成品与来源/版本检查，再执行：

```sh
python -X utf8 scripts/official_publications.py check --root .
python -X utf8 scripts/public_accessions.py assign --root .
python -X utf8 scripts/public_accessions.py check --root .
```

同一个assign同时生成registry、简短 `NUMBERED_INDEX.md` 与 `numbered/` 下四类编号页。先完整验证数据，再原子保存registry，随后原子替换索引；如果索引写入失败，已经分配的registry仍保留，恢复可写后重跑assign沿用旧号重建索引。不要回退registry以重用已分配号。check只报告漂移，不修复、不分号、不推送。

缺少可信编号历史时不允许把既有状态当成全新系统。非Git工作副本需要由原维护者保存的独立旧registry：

```sh
python -X utf8 scripts/public_accessions.py assign --root . --baseline <受信任的旧registry副本>
python -X utf8 scripts/public_accessions.py check --root . --baseline <同一旧registry副本>
```

基线文件不写入公开登记。没有基线的首次状态，只能对最初那份完整manifest检查；随后增量需要Git历史或独立可信旧登记。不得把当前registry本身传为baseline。

## 不删号的检查

工具只读比较最近的已提交编号登记版本；基线中的主号、类型、旧版本、aliases、F号和旧位置不得删除、改写或退计数器。每种主号及每条F计数器都须闭合、无重复或缺号。当前manifest每个源ID必须有相同kind、标题、来源URL和准确版本映射；当前清单不再包含的旧条目保留历史号，不能拿去分配给别人。

公众号转载卡、原文与视频页保留各自原编号；转载关系经微信原身份与已保存原文交叉核对后在阅读页给出直达链接。图像正文按原图顺序引用独立图像编号；历史离线快照不标为当前微信在线回读。字幕的历史发行版、所有者API实际下载版和独立本地机器稿分别编号，实际平台语言码与缺句情况保留。

CI应使用完整Git历史（checkout的fetch-depth设0），或提供明确受信任baseline。已有编号的浅克隆默认拒绝，避免只看当前HEAD就冒称检查过追加历史。首次初始化未被Git跟踪时可验证最初快照；提交主分支后，完整历史能读取首次登记作为基线而通过，depth=1的CI仍会拒绝，因此首次含编号的提交也必须设置fetch-depth:0。首次未提交初始化可检查最初完整快照；一旦既有状态需要更新，不以“没有旧文件”代替基线。

编号先调用公开成品校验器检查当前来源、批准和版本；编号工具本身不重新抓官网、不上传、不读取PC私有原片，也不声称旧平台状态今天已回读。历史版本URL保留原记录，当前可访问性由相应发布流程验收。

## 维护与阅读

[NUMBERED_INDEX.md](../NUMBERED_INDEX.md) 是简短分类入口，分别进入 `numbered/documents.md`、`captions.md`、`research.md`、`images.md`。分类页列主号、原文与文件子号，目标每页小于512KiB（在500KiB处提前分页留余量）；大分类按固定100号段分页，主号与F号均不改变。仓库文件从numbered目录使用 `../published/`，登记使用 `../registry/`，Release仍直接采用实际download_url。成员很多时只预览少量位置，全部文件号与版本位置都在 [registry/public-accessions.json](../registry/public-accessions.json)，没有省略登记。check比较所有生成页并拒绝遗留分页；assign只清理自己命名的过期生成页，不删除其他文档。成品条目数、文件字节版本数、存储位置数各有口径，不能加成“总作品数”。

```sh
python -X utf8 -m unittest discover -s tests -p test_public_accessions.py -v
```

Mac/PC继续遵守单写入者与Git分支交接。文件锁只协调同一系统的分配过程；共享Git登记并非跨机器自动锁。原catalog、PC私有计数器、原编号与素材原件不由这套命令改动。
