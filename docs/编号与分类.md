# 编号与分类

档案把“做过什么”“发生了哪次事件”“留下什么材料”分开记录，再建立关联。这样同一事件的多机位、一条视频中的多个项目、原片和修复版、不断改进的字幕，都能保留自己的位置。

## 记录层级

| 对象 | 回答的问题 | 记录原则 |
| --- | --- | --- |
| 项目 project | 这是什么持续开展的作品或实践？ | 名称可以修订，身份标识保留；同名作品不凭名称合并 |
| 资料集合 collection | 这批材料是从哪里、按什么批次接收的？ | 保留来源批次；集合与项目可以是多对多关系 |
| 事件 event | 在什么时候、什么场合发生了什么？ | 日期记精度与依据；由文件夹暂建的事件明确标为候选 |
| 素材 asset | 这是一件什么档案材料？ | 与项目、事件及其他材料建立关联 |
| 物理文件 file | 电脑里保存的究竟是哪份字节内容？ | 记录大小、格式、哈希、损坏和派生关系，不含公开的本机位置 |
| 字幕 subtitle | 哪个版本的文字对应哪份视频？ | 记录语言、生成方式、版本、时间轴和审核范围 |
| 发布 publication | 哪个版本被报告在什么平台可访问？ | 人工声明与平台核验分别记录；手填视频 ID、可见性和观察时间不等于平台回读证据 |

初期从文件登记材料时，素材与物理文件可能一一对应。后续核实它们是否描述同一个档案对象时，再通过有依据的关系连接；不要批量猜测合并。

## 身份标识与展示编号

每条记录有稳定的身份标识，另有便于口头引用、排序和查找的展示编号。展示编号采用 `P4-` 前缀与对象类型及流水号，例如项目目录中的 `P4-P000001`。编号不包含日期或项目名，改正日期或补全展示标题不需要重新编号。

当前导入器保证同一路径的增量编号稳定。已建档文件移动或改名时，须先登记并迁移私有路径键；它不会自动识别这种移动，未迁移就导入会生成候选新记录。同一路径的字节版本变化保留素材编号并记录新的文件版本，旧文件版本继续保留；旧版的人工审核结论不能直接沿用到新版。

旧的 `p4-evidence-v1` 记录已经拥有身份标识时，保留旧标识并建立对照。尚未确认是否与旧条目对应的，保持“待对齐”；新展示编号不能被说成已经替换或统一了旧系统。合并、拆分、撤回和重复记录都保留旧编号的去向及理由，编号不回收再用。

首次导入分配编号后，后续导入必须使用同一份登记状态。不要删除本地登记状态后凭目录排序重新编号。维护者在迁移设备时，也应备份私有的路径映射和编号登记，见 [保存与恢复](保存与恢复.md)。

## 分类可以逐步完善

优先使用有来源的分类：作品实践、排练、演出、工作坊、读本、讨论、筹备、传播、参考材料。尚未核实时使用待分类；允许一项素材关联多个项目或事件。分类描述用途和内容，不判断艺术价值。

需要特别区分：

- 原始记录、修复版、剪辑版、压缩发布版与工程内副本。
- P4 现场材料与外部参考材料。
- 已确认的项目材料、混合素材与待确认公开范围的材料。
- 原语字幕、翻译字幕、中英双语字幕与不同修订版本。

同一文件夹可能混有不同项目；同一项目也可能跨多个日期和资料集合。初期目录关系只作为待核实的归类线索。

## 日期与时间轴

记录事件日期时说明来自文件名、片头、原始拍摄元数据、节目单还是其他来源，并记录精度。只知道年份就保留年份；只有文件名线索就明确标注线索来源。文件修改时间仅帮助本地管理，不直接作为事件发生时间。

视频时间码默认采用对应源文件起点为零的 `source_zero`。剪辑、删除片头或拼接后，必须建立该版本与源视频之间的时间段对应；没有验证的区间不外推。引用字幕时同时记录字幕版本和 cue 编号，避免后续分句调整造成定位漂移。

## 重复与修复

SHA-256 相同可以支持“这两份文件字节相同”，不能独自支持“这是同一个事件”或“可以删除其中一份档案记录”。同名、同大小、时长相近都只能列为候选重复。

修复记录要说明原版、使用的参考、输出版本、实际可读取时长与全程解码结果。能打开索引与完整音视频解码通过分别记录；没有证据时，不称原始内容已全部恢复。
